# ELIAS NET 五項產品線與企業 AI 能力規格

**文件狀態：** v1.0，產品線擴充與網站實作基準  
**文件作者：** Manus AI  
**適用範圍：** ELIAS NET 虛擬科技公司官網、產品介紹、Concept／Lab／Pilot 規劃

## 一、產品線擴充決議

ELIAS NET 產品由三項擴充為五項，但不是任意增加產品名稱，而是按照目前企業 AI 平台可支援的能力，形成五個互補的工作場景。現代企業 AI 已能將大型語言模型與外部資料檢索結合，提供文件問答、內容生成與企業資料存取；文件理解也可以處理數位文件、掃描文件、Office 檔案與 HTML，並進行文字、表格與結構抽取。[1]

企業 AI 也開始支援具備推理、規劃與行動能力的 Agent，以及由專業 Agent 分工的多 Agent 工作流；官方平台同時強調工具、模型、執行環境、政策控制、評估、可觀測性與治理，而不是只有聊天介面。[2] 企業產品還可延伸到語音轉文字、翻譯、影像與影片理解、文件處理、向量搜尋、MLOps 與 AI readiness 顧問等能力。[3]

因此，ELIAS NET 五項產品採用「工作場景產品＋共同控制層」結構：五個產品回答不同的企業工作問題；Elias Control Layer 則是跨產品的資料、權限、人工核准、工具存取、記錄、評估與成熟度控制層，不另外算作第六項對外產品。

## 二、五項產品總覽

| 編號 | 產品名稱 | 主要工作問題 | 核心 AI 能力 | 初始成熟度建議 |
|---|---|---|---|---|
| 01 | **Elias Knowledge Hub** | 企業如何從核准文件與知識中找到可信答案？ | RAG、語意搜尋、文件解析、引用、權限過濾、摘要 | Lab → Pilot |
| 02 | **Elias Service Copilot** | 服務團隊如何快速理解案件並提出可審核的回應？ | 分類、摘要、意圖辨識、回覆草稿、路由、人工核准 | Concept → Pilot |
| 03 | **Elias Ops Sentinel** | 維運團隊如何把告警、紀錄與事件脈絡整理成可判斷的資訊？ | 事件關聯、日誌分析、根因假設、異常偵測、唯讀診斷、風險閘門 | Concept → Lab |
| 04 | **Elias Workflow Orchestrator** | 跨系統的多步驟工作如何由 Agent 協調，但不失去人的控制？ | Agent 規劃、工具調用、流程狀態、任務分工、核准節點、稽核軌跡 | Concept |
| 05 | **Elias Signal Studio** | 文件、語音、影像與結構化資料如何轉成可用的決策簡報？ | 多模態理解、OCR、語音轉錄、翻譯、抽取、報告草稿、來源追溯 | Concept → Lab |

## 三、產品一：Elias Knowledge Hub

### 定位

Elias Knowledge Hub 是企業知識與文件理解方案，將核准的文件、政策、流程、FAQ、會議紀錄與知識資產轉成可搜尋、可引用、可追溯的回答。其設計基礎是 RAG：將大型語言模型與外部資料檢索結合，讓回答可以使用模型訓練資料以外的企業資料，同時讓組織控制模型使用哪些資料。[1]

### 工作流程

```text
核准資料來源 → 文件解析與結構化 → 權限與版本檢查 → 語意檢索 → 回答＋來源引用 → 人員確認／回饋
```

### 可支援能力

產品可以支援文件內容搜尋、語意分段、表格與標題理解、跨語言查找、回答摘要、來源引用、文件版本判斷與權限過濾。文件解析可以處理 PDF、掃描影像、Office 檔案與 HTML 等類型，但實際可支援的檔案格式、語言與準確率仍需在 Pilot 階段驗證。[1]

### 控制邊界

Knowledge Hub 不應回答沒有來源的高風險問題，不應把未核准文件當成正式政策，也不應將使用者無權存取的文件片段帶入回答。每個回答應顯示來源、文件版本、檢索時間與「需要人工確認」的條件；查不到可信資料時應回覆無足夠證據，而不是自行補寫答案。

### 產品視覺

主視覺採用寫實企業知識檔案室，文件卡片、引用線、版本標籤與權限閘門以抽象方式呈現。網站內的精確流程使用 HTML／SVG，不把文件名稱、數字或關鍵治理規則只放在生成圖片中。

## 四、產品二：Elias Service Copilot

### 定位

Elias Service Copilot 是服務台、客服、客戶成功與內部支援團隊的 AI 協作方案。它把案件內容整理成摘要，協助判斷意圖、推薦知識、草擬回覆與分派路由；但正式回覆、權限異動、退款、合約變更或其他高影響動作必須經過適任人員確認。

### 工作流程

```text
案件／對話輸入 → 語意與優先級判斷 → 相關知識檢索 → 摘要與回覆草稿 → 人員核准 → 發送／建立下一步 → 留存決策紀錄
```

### 可支援能力

產品可支援案件分類、情緒與意圖標記、長對話摘要、重複案件合併建議、知識引用、回覆草稿、多語翻譯、路由建議與服務品質回饋。這些能力應被描述為「協助」與「建議」，而不是無條件自動代表公司對外承諾。

### 控制邊界

Service Copilot 不可自行發送高風險回覆、修改帳務、改變客戶權限、承諾補償或關閉案件。任何對外輸出都應記錄使用的知識來源、模型建議、人工修改者、核准時間與最終版本。

### 產品視覺

主視覺採用寫實服務控制台與一名工作者檢查 AI 建議的場景。動態設計表現案件由雜訊變成清楚的摘要，最後停在「等待人工核准」狀態；不以自動完成動畫暗示系統已經可以無人值守。

## 五、產品三：Elias Ops Sentinel

### 定位

Elias Ops Sentinel 是維運、SRE、網路與資安團隊的事件情報方案，將告警、日誌、變更紀錄、服務依賴與時間線整理成可判斷的事件視圖。企業 AI 平台目前已將 IT service desk、事件調查與 cyber defense 視為可由 Agent 協助的工作場景，但這些場景仍需要政策、工具、執行環境、評估與治理。[2]

### 工作流程

```text
告警／日誌／變更 → 事件關聯與時間線 → 異常與根因假設 → 唯讀診斷 → 風險分級 → 人員核准後才可執行下一步
```

### 可支援能力

產品可以支援告警聚合、相關事件關聯、日誌與變更紀錄摘要、初步根因假設、維運知識檢索、影響範圍說明、處置建議、事件報告草稿與事後回顧整理。可將高風險命令、憑證、網路設定與資料刪除等動作列為禁止自動執行項目。

### 控制邊界

第一階段以「觀察、解釋、建議」為主，不宣稱可完全自動修復生產環境。所有工具存取必須採最小權限，診斷與變更分離，生產操作必須有人工核准、雙人確認或既定的變更流程。任何自動動作都需要完整的工具呼叫、參數、操作者、核准者與結果記錄。

### 產品視覺

主視覺採用深色維運控制室，呈現事件時間線、服務依賴、唯讀放大鏡與政策閘門。動態效果讓訊號從多個來源匯聚成一條可讀時間線，當動作需要人工核准時停下，而不是以紅色警報與快速跳動製造焦慮。

## 六、產品四：Elias Workflow Orchestrator

### 定位

Elias Workflow Orchestrator 是跨資料來源、工具與部門的 Agent 工作流協調方案。它不是單一聊天機器人，而是把任務拆成步驟、安排工具與專業 Agent、管理狀態、等待核准，再把結果交回人員。企業 Agent 平台目前可以支援推理、規劃、行動、多步驟工作與多 Agent 分工，但真正的企業落地仍取決於工具權限、執行環境、評估與治理。[2]

### 工作流程

```text
目標與限制 → 任務拆解 → 選擇工具／Agent → 取得資料 → 中間結果檢查 → 人工核准 → 執行允許動作 → 輸出與稽核
```

### 可支援能力

產品可支援自然語言任務定義、工作步驟規劃、專業 Agent 分工、工具與 API 調用、狀態追蹤、條件分支、人工核准、失敗重試、結果摘要與工作流評估。可把報告整理、跨系統資料比對、內部研究、供應商資料初步整理與內容草稿列為 Concept／Lab 範例。

### 控制邊界

產品不應宣稱 Agent 可以自行處理所有企業流程。每個工作流必須定義允許工具、資料範圍、最大執行時間、最大成本、可重試次數、停止條件與升級對象。付款、刪除、權限變更、法律／醫療／高風險決策與對外承諾應預設為人工核准或禁止自動執行。

### 產品視覺

主視覺採用寫實的企業工作流控制室，將任務拆成幾個可見節點，每個節點有工具、狀態、責任者與核准標記。動畫採用節點逐一解鎖、局部路徑描繪與停等狀態，讓訪客看見「Agent 如何受控制」，而不是只看見一個會發光的聊天泡泡。

## 七、產品五：Elias Signal Studio

### 定位

Elias Signal Studio 是多模態企業資訊整理方案，把文件、掃描影像、表格、語音、圖片、影片片段與結構化資料轉成可搜尋、可比較、可交接的工作素材。Google Cloud 的官方 AI 產品分類已將 Speech／Text／Language、Image／Video、Document／Data APIs 與多模態能力視為企業 AI 產品的一部分。[3]

### 工作流程

```text
文件／語音／影像／表格 → OCR／轉錄／結構抽取 → 欄位與來源確認 → 摘要與比較 → 報告草稿 → 人員驗證 → 匯出可追溯成果
```

### 可支援能力

產品可以支援文件 OCR、表格與欄位擷取、會議轉錄、語音摘要、圖片內容理解、影片片段標記、多語翻譯、文件比較、資料欄位標準化與報告草稿。所有抽取結果都應保留原始來源與頁碼、時間戳或影像位置，以方便人工回查。

### 控制邊界

多模態輸出可能受影像品質、聲音雜訊、手寫內容、語言、版面與上下文影響，因此第一階段必須以「加速整理與初步分析」描述，不宣稱百分之百準確。高風險文件、合約、財務、醫療與身分資料應採更嚴格的人工審查與資料保留規則。

### 產品視覺

主視覺採用多模態資料工作室，呈現一份文件、一段聲波、一張影像與結構化資料匯入同一個受控工作區。生成圖片只負責營造情境；OCR 文字、欄位值、時間戳、來源與核准狀態用 HTML／SVG 實際呈現。

## 八、共同控制層：Elias Control Layer

五項產品共用 Elias Control Layer，作為 ELIAS NET 的平台能力，而不是額外宣稱的第六項產品。它至少包括資料來源與版本、角色權限、最小工具存取、人工核准、內容過濾、提示與模型設定、輸出引用、事件記錄、評估集、成本與延遲觀察、錯誤處理、停止條件與成熟度閘門。

每個產品介紹都必須回答五個治理問題：AI 使用了哪些資料；哪些人可以看見與執行；哪些動作必須人工核准；系統如何留下證據；如果輸出不可靠或服務失效，如何停止、回復與通報。這些問題將 Knowledge Hub、Service Copilot、Ops Sentinel、Workflow Orchestrator 與 Signal Studio 統一成一間有治理能力的公司，而不是五個互不相干的 Demo。

## 九、五項產品的彼此分工

| 產品 | 主要輸入 | 主要輸出 | 人工核准重點 | 不負責的範圍 |
|---|---|---|---|---|
| Knowledge Hub | 核准文件、政策、知識 | 引用式答案、摘要、搜尋結果 | 答案是否有足夠來源、是否可對外使用 | 無來源的自由回答、未授權資料存取 |
| Service Copilot | 案件、對話、服務歷史 | 分類、摘要、回覆草稿、路由建議 | 對外回覆、補償、權限、案件結案 | 無人監督的高風險客戶承諾 |
| Ops Sentinel | 告警、日誌、變更、依賴 | 事件脈絡、根因假設、診斷與處置建議 | 生產變更、命令、憑證與高影響操作 | 預設自動修復生產環境 |
| Workflow Orchestrator | 目標、限制、工具與資料 | 任務計畫、中間狀態、執行結果 | 每個高影響工具呼叫與流程解鎖 | 無限制自主 Agent、無邊界工具使用 |
| Signal Studio | 文件、語音、影像、表格、影片 | 結構化欄位、轉錄、摘要、比較、報告草稿 | 抽取準確性、來源、敏感文件與正式報告 | 未經審核的正式法律／財務／醫療判斷 |

## 十、官網呈現方式

產品導覽不應只有「五張卡片」。首頁可以使用五項產品的摘要卡，但每一張卡都要有產品狀態、適合誰、主要工作問題、三到四步流程、控制邊界與下一步入口。點擊後可進入同一頁的詳情抽屜，或逐步拆成五條獨立靜態路由。

產品排序建議先放 Knowledge Hub 與 Service Copilot，讓訪客先理解企業搜尋與人機協作；接著放 Ops Sentinel，展示可靠性與安全；再放 Workflow Orchestrator，展示 Agent 與工具協調；最後放 Signal Studio，展示多模態與未來擴張能力。這個順序由「理解資料」走到「協作工作」，再走到「管理系統」、 「協調 Agent」與「處理多模態訊號」，能形成清楚的能力階梯。

產品視覺可以各自不同，但共用深藍、青色、香檳金、低飽和玫瑰色與細線資料界面。每項產品生成一張主視覺，流程示意由網站原生元件完成；這樣既能達到科技公司官網的視覺完成度，又不會把產品準確性與治理內容交給圖片生成模型。

## 十一、分階段成熟度

| 階段 | 五項產品的公開說法 | 必須具備的證據 |
|---|---|---|
| Concept | 說明問題、假設與可能的工作流程 | 產品假設、風險、禁止宣稱事項 |
| Lab | 展示可運作的受控原型 | 測試資料、模型／流程限制、失敗案例 |
| Pilot | 在明確資料與使用者範圍內驗證 | 使用者、資料、權限、指標、人工核准與回顧 |
| Production | 只有在完成可靠性、資安、維運與品質驗證後使用 | 上線紀錄、監控、回滾、支援、稽核與正式責任人 |

目前官網可將 Knowledge Hub 標示為 Lab → Pilot，Service Copilot 標示為 Concept → Pilot，Ops Sentinel 標示為 Concept → Lab，Workflow Orchestrator 標示為 Concept，Signal Studio 標示為 Concept → Lab。這樣新增產品後仍能維持 ELIAS NET「可用・可控・可證明」的誠實承諾。
